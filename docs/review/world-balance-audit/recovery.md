# 재개·복구 및 진단 이력

2026-11-08 KST에 사용 한도 재설정 후 작업을 재개했다. 계정의 한도 상태 자체는 확인할 수 없으나 도구 실행은 가능했다. 이전 `/tmp/storm-background-work`와 미커밋 분석 자료는 환경의 임시 경로 초기화로 존재하지 않았다. GitHub 작업 브랜치는 기준 `07c3d34331770f53817ca513241949ec19fe8dbe`, main은 `653ac838e32fbf8276853058b75041703af4f079`로 유지돼 있었다.

기존 `/workspace/helicopter-game` 복사본은 변경하지 않고 원격의 지정 브랜치를 별도 복사본으로 복구했다. 대화에 남아 있던 정확한19개 표시·기록 보존 차분, 보존 검사, 측정 정책을 복원했다. 여기 기록한 최종 분석 원본과 회귀 결과는 복구 후 실제 재실행 결과다. 이전 관찰을 새 로그인 것처럼 합산하지 않는다.

이전 진단에서 확인한 도구 문제는 다음과 같다. 당시 원본 로그는 임시 경로와 함께 사라져 복구할 수 없으므로 이 파일은 **요약 기록**이며 원본 로그를 대체하지 않는다.

- 초기에 존재하지 않는 `gameScoring.getRun()`을 호출했다. 해당 진단 필드를 제거했다.
- 이전 게임의 잔여 `fireCooldown`이 초기 상태를 흔들 수 있어 진단 시작만 새 세션과 같은0으로 통일했다. 제품의 발사 대기시간 로직은 수정하지 않았다.
- 정지 표적의 독자 EPS 발사 계산 대신 원래 `fireCooldown` 코드 조각을 그대로 실행하고60/120Hz를 구분했다.
- 반경·탄 이동과 보스 HP는 원래 함수를 사용한다. 자동 정책에 강제 무적·즉사·부활은 없다.

현재 복구본은 `/workspace/scratch/world-balance39-checkpoint/`에도 체크포인트로 저장한다. 대용량 `dist`는 원본 자산에서 재생성할 수 있어 체크포인트 압축본에서 제외하며, 실제 결과물은 작업 브랜치에 커밋한다. 본문에 제시한9회 정상 진행,144개 정지 표적 조건,480개 보스 조건,432개 일반 단계 조건은 복구 후 확보한 JSON을 기준으로 한다.

이전 환경에서의 자원 종료 이력은 기존 DEVELOPMENT_LOG의70항과 해당 기존 보고서에 그대로 보존돼 있다. 이번 복구 후 자원 이벤트와 회귀 실패는 별도로 집계한다.
